# OS-Themed UI + Soft Gray 终端主题 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add two new UI themes (Windows 11 + macOS 26) that auto-follow system light/dark via CSS `@media (prefers-color-scheme: dark)`, and one new terminal theme (`uniterm Soft Gray`) with light gray background and ANSI palette tuned for character distinguishability — without breaking any existing theme.

**Architecture:** JS-side: extend the `Theme` type union, append `<el-option>` entries in two picker files, add 2 i18n keys × 9 locales, add one terminal theme entry + `getXtermTheme()` branch. CSS-side: append two new `[data-theme]` blocks to `frontend/src/style.css`, each containing a light variable set + a `@media (prefers-color-scheme: dark)` block with dark overrides, plus scoped component-level overrides for `el-tabs` / `el-button` / `el-input` / `el-dialog` / `el-menu` / `el-checkbox` / `el-switch` / scrollbar / `AppHeader` / `Sidebar` / `SettingsTab` / `BaseTerminal`. JS theme-application code is **untouched** — `data-theme="win11"` / `data-theme="macos26"` already do the right thing once the CSS exists.

**Tech Stack:** Vue 3 (Composition API), TypeScript 5.3, Element Plus 2.5, Vite 5, xterm.js 5.5, vitest 4.1 (colocated `.test.ts`).

**Spec:** `.planning/specs/2026-07-28-os-themes-design.md` (committed at `142f84b`).

## Global Constraints

- **No new dependencies** — no npm install, no go get.
- **Zero regression** — the three existing UI themes (`dark` / `deep-blue` / `light`) and 27 existing terminal themes must render pixel-identical. All new rules are namespaced under `[data-theme="win11"]` or `[data-theme="macos26"]` selectors.
- **CSS-only OS mimicry** — no Win32 DWM, no macOS NSVisualEffectView. Mica and Liquid Glass are simulated via subtle `linear-gradient` / `radial-gradient` on `body`.
- **Auto-toggle by CSS, not JS** — deep/light switching is handled by `@media (prefers-color-scheme: dark)` inside the theme block. No reactive JS needed; existing `<html data-theme="...">` writer is unchanged.
- **Existing `system` mode behavior is unchanged** — it already follows OS appearance.
- **Conventional commits** — `feat(theme):` for new themes, English title + bilingual body, `---` separator.
- **Verification gate** — `npm --prefix frontend run build` must pass after every task that touches frontend code.
- **Manual visual gate** — final task uses `wails dev` to verify the spec §8.1 checklist.
