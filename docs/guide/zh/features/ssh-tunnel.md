# SSH 隧道

uniTerm 内置 SSH 隧道管理器，支持三种转发模式，可创建、管理和监控多个隧道连接。

![SSH 隧道](/imgs/ssh_tunnel_light.webp)

## 隧道管理器

SSH 隧道在侧边栏独立标签页中管理，也可在「设置 → 隧道」中管理。点击左侧边栏的隧道图标打开隧道面板，查看所有已创建的隧道及其运行状态。面板顶部提供搜索框。

- **状态指示灯** — 绿色表示运行中，黄色表示连接中或等待重连，灰色表示已停止，红色表示错误（悬停可见错误详情）
- **右键菜单** — 右键隧道项可启动、停止、编辑或删除隧道（运行中、连接中或等待重连时需先停止才能编辑）
- **拖拽分组** — 拖拽隧道项到分组中，便于分类管理
- **凭据补全** — 启动出口 SSH 连接未保存凭据的隧道时，会弹出对话框提示输入，而不是直接失败
- **启动失败提示** — 启动失败时如实提示原因，并附配置测试与 SSH 命令示例

## 三种转发模式

### 本地转发 (-L)

将远程服务器的端口映射到本地，通过本地端口访问远程服务。

**典型场景**：远程服务器的数据库（如 MySQL :3306）不对外开放，通过本地转发映射到 `localhost:3307` 后，本地工具即可直接连接。

```
本地端口 :3307  →  SSH 隧道  →  远程数据库 :3306
```

### 远程转发 (-R)

将本地端口暴露给远程服务器，远程主机可通过其本地端口访问你的本地服务。

**典型场景**：本地开发的服务需要让远程服务器或外部用户访问，如本地 Web 应用通过远程转发让公网服务器可访问。

```
远程端口 :8080  →  SSH 隧道  →  本地服务 :3000
```

### 动态转发 (-D, SOCKS5)

在本地搭建 SOCKS5 代理，浏览器或其他应用通过代理访问远程网络中的所有服务。

**典型场景**：通过跳板机访问公司内网的所有 Web 系统、API 等，无需逐个配置端口转发。

```
浏览器  →  SOCKS5 :1080  →  SSH 隧道  →  远程网络中的所有服务
```

## 创建隧道

1. 在隧道面板中点击 **新建隧道**
2. 选择 **SSH 连接**作为跳板机（需先在连接列表中创建 SSH 连接）
3. 选择 **转发模式**：本地转发、远程转发或动态转发
4. 根据模式填写本地地址/端口和目标地址/端口（动态模式仅需本地端口）
5. 可选：设置 **自动启动**，应用启动时自动连接该隧道
6. 可选：开启 **自动重连**，设置基础重试间隔（默认 120 秒，可设为 1–86400 秒）和随机浮动比例（0–100%，默认 0%）

## 自动启动

开启自动启动后，隧道会在 uniTerm 启动时自动连接。适用于需要始终保持连接的隧道，如开发环境的 SOCKS5 代理。

## 自动重连

自动重连按隧道单独设置，适用于本地转发、远程转发和动态转发。启用后，SSH 连接异常断开或连接尝试失败时，隧道会显示「等待重连」，在设定的间隔后再次连接；如果失败，将继续重试。间隔从检测到断线或连接尝试失败时开始计算。

随机浮动为 0% 时使用固定间隔。例如，基础间隔设为 120 秒、随机浮动设为 ±20% 时，每次重试会重新随机等待 96–144 秒。随机等待时间至少为 1 秒。

点击 **停止**、删除隧道或退出 uniTerm 会取消自动重连；再次点击 **启动** 后才恢复。自动重连与自动启动可分别启用，测试配置不会启动后台重试。

自动连接需要可用的 SSH 凭据。手动启动时输入的临时凭据仅在当前隧道运行期间用于重连，不会因此保存到磁盘；应用重启后仍需要已保存的凭据。

## macOS 与 Windows：多级跳板连接

macOS 和 Windows 使用相同的多级 SSH 跳板配置。普通连接中的「SSH 隧道」会递归读取所选跳板的上一级跳板，按从外到内的顺序连接。每一跳使用各自的用户名、密码、私钥或密钥库身份。

### 配置示例

假设访问路径为 `本机 → 跳板 A → 跳板 B → 目标 C`：

| 保存的连接 | 主机地址示例 | 「高级配置 → 网络 → SSH 隧道」 |
| --- | --- | --- |
| 跳板 A（SSH） | `gateway.example.com:22` | 留空，本机可以直接访问 A |
| 跳板 B（SSH） | `10.0.0.10:22` | 选择跳板 A |
| 目标 C（SSH） | `10.0.1.20:22` | 选择跳板 B |

1. 新建并保存跳板 A 的 SSH 连接，配置 A 的登录凭据。
2. 新建跳板 B 的 SSH 连接。在「高级配置 → 网络 → SSH 隧道」中选择 A，配置 B 的登录凭据并保存。
3. 新建目标 C 的连接，填写 C 的实际地址和登录凭据。在「SSH 隧道」中选择 B。
4. 点击「测试连接」检查配置，再连接 C。uniTerm 会依次建立 A、B 和 C 的连接，无需提前打开 A、B 的终端标签页。

目标地址从最后一跳访问。例如，C 的域名只需能被 B 解析，B 的域名只需能被 A 解析。不要将 C 的地址改成 A 的地址。单个跳板只需省略 B，将 C 的「SSH 隧道」设为 A。

同样的配置可用于提供「SSH 隧道」选项的 TCP 连接，例如 SFTP 和 RDP。每个连接按其目标协议填写端口和凭据；跳板连接始终使用 SSH。

### macOS 使用方式

在 macOS 版 uniTerm 中按上述步骤保存 A、B、C，然后直接连接 C。客户端使用内置 SSH 实现，无需开启 macOS「远程登录」来使用外部跳板。

使用私钥路径时，选择 Mac 本机的私钥文件；使用 SSH Agent 时，确保启动 uniTerm 的环境可访问 `SSH_AUTH_SOCK`。从 Windows 同步来的私钥路径需要改为 Mac 上的实际路径，也可改用密钥文本或密钥库身份。

### Windows 使用方式

在 Windows 版 uniTerm 中使用相同的 A、B、C 配置。客户端无需安装 Windows OpenSSH Server，也无需通过 WSL 执行跳转命令。

使用私钥路径时，选择 Windows 本机的私钥文件；使用 SSH Agent 时，uniTerm 优先使用 Pageant，其次使用 Windows OpenSSH Agent。从 macOS 同步来的私钥路径需要改为 Windows 上的实际路径，也可改用密钥文本或密钥库身份。

### 生命周期与失败处理

- 普通连接的跳板链随目标连接建立。关闭目标会话或退出应用时，整条链一并关闭；应用启动时不会单独启动这条链。
- 多级链的每一跳都需要可用凭据。上游跳板请提前保存凭据、引用密钥库身份或配置 SSH Agent；当前凭据补全对话框不会逐级询问所有上游跳板的密码。
- 若某一跳连接或认证失败，已建立的上游 SSH 连接会关闭。检查错误中标识的主机地址及对应连接的凭据。
- 若提示跳板不存在，检查对应连接是否被删除；若提示 `loop`，检查是否存在 A 选择 B、B 又选择 A 等循环引用。
- 跳板 SSH 服务需要允许 TCP 转发。如果使用 uniTerm 内置 SSH 服务作为跳板，需要包含 [PR #1406](https://github.com/ys-ll/uniterm/pull/1406) 的版本，并在跳板机器上手动启动「本地服务 → SSH/SFTP 服务」。内置服务的能力与客户端多跳配置分别提供。

### 与独立隧道管理器的关系

独立隧道管理器同样会递归读取所选 SSH 连接的跳板配置。以上例为例，新建隧道时选择 B 作为「SSH 连接」，连接路径为 `本机 → A → B`，再由 B 转发到目标服务。本地、远程和动态转发模式保持各自的语义。

普通连接用于在 uniTerm 中直接打开目标会话；独立隧道适合向浏览器、数据库工具等其他程序提供端口或 SOCKS5 代理。需要随应用启动的独立隧道，可以单独启用「自动启动」。

## 参照对象与配置对应

以下对照针对客户端跳板连接，不表示这些客户端本身都提供 SSH 服务端。

| 参照对象 | 官方配置方式 | uniTerm 对应方式 |
| --- | --- | --- |
| Xshell | 在代理设置中选择 `JUMPHOST`，使用 `Next proxy` 串联多级跳板 | 在每个 SSH 连接中选择上一级「SSH 隧道」，目标选择离目标最近的一跳 |
| MobaXterm | 在会话的 `Network settings` 中配置 `SSH gateway`；支持多个 SSH jump hosts | 在普通连接或独立隧道中引用已保存的跳板连接链 |

参考官方文档：[Xshell Proxy Setting](https://netsarang.atlassian.net/wiki/spaces/ENSUP/pages/2237304738/Proxy+Setting)、[MobaXterm Network settings](https://mobaxterm.mobatek.net/documentation.html#4_10)、[MobaXterm 多跳支持更新记录](https://mobaxterm.mobatek.net/download-home-edition.html)。
